# Windows Realtime Interception Harness Assessment

An ordinary diagnostic wrapper can prove only calls voluntarily routed through that wrapper; it cannot observe static libsamplerate/CRT/Kernel32 imports. Such a wrapper would make its own positive controls pass while leaving the target process path unobserved, so it is not valid for this gate. A usable implementation needs import-address-table patching or a verified detour mechanism for executable and static-library call paths, including recursion-safe thread-local callback marker/counters, then positive/negative/thread-isolation controls.

The repository now contains `option_b_windows_iat_crt_harness`, an x64 loaded-image PE IAT parser and VirtualProtect patch/restore harness. It resolves the final executable's named IAT slots at runtime, so the hook point is before Kernel32 forwarding (and before the API-set CRT provider is dispatched). On the recorded Windows Release run, common CRT imports resolve through `api-ms-win-crt-heap-l1-1-0.dll`; all mandatory Windows APIs resolve through `KERNEL32.dll` IAT entries. Positive callback controls, full negative callback controls, cross-thread isolation, patch/restore/reinstall lifecycle, and first-use plus steady-state static-libsamplerate `src_process` smoke all passed.

This establishes the listed IAT routes and categories for this executable only. It does not prove routes absent from the import table, dynamically resolved calls, other loaded modules, or the remaining allocator routes. Harness status: **mandatory IAT coverage validated for the recorded executable; broader Windows realtime proof remains incomplete**.
